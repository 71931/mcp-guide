MCP 傻瓜配置教程（瑞幸咖啡 / 麦当劳 / 高德地图）

本教程面向完全没接触过 MCP 的用户。按顺序照做，全程约 15 分钟。 文中所有页面步骤、按钮名称均来自 2026-09-10 的实际页面访问记录，非推测。 你只需要填 3 个空：瑞幸 Token、麦当劳 Token、高德 Key。

第 0 章 先搞明白这是什么

一句话：MCP 是让 AI 能"动手"的插件协议。

原来的 AI 只能聊天，问它"附近有没有瑞幸"它只能瞎猜。装上 MCP 之后，AI 能真的去查门店、看菜单、下单、算路线——因为它被授权调用瑞幸/麦当劳/高德官方提供的接口。

配置 MCP 一共就三步：

  1. 拿钥匙——去官方平台领一串字符，代表"这是我本人授权"
  2. 填配置——把钥匙填进一个 JSON 配置里
  3. 重启客户端——让 AI 重新加载插件

就这三步。下面开始。

第 1 章 开始前的准备清单

序号 需要准备 说明
1 一部手机 领钥匙全程手机浏览器就能完成
2 你的手机号 瑞幸和麦当劳都要短信验证码登录
3 一个支持 MCP 的客户端 比如 Cherry Studio、Cursor、TRAE、Claude Desktop 等，见第 2 章
4 记事本 领到的 3 串字符先粘进去存着，等会要用

先说清楚：这 3 把钥匙能干什么、不能干什么。

钥匙 能干什么 限制
瑞幸 Token 查门店、看菜单、下单、查订单 改杯型/糖度接口有缺陷；部分场景不支持配送
麦当劳 Token 点餐、领券、查积分、积分商城、抽奖 每分钟最多 600 次调用，超了报 429
高德 Key 算路线、搜周边、地名转坐标 不能替你打车、不能下单

第 2 章 第一步：找到你客户端的 MCP 配置入口

不同客户端入口位置不一样，但配置内容是完全一样的（第 4 章会给）。先找到入口：

2.1 常见客户端入口位置

客户端 MCP 配置入口 导入方式
Cherry Studio 设置 → MCP 服务器 点「添加」→ 点「从 JSON 导入」→ 粘贴 JSON → 点「确定」
Cursor 【设置】→【Tools & MCP】→【Add Custom MCP】 粘贴 JSON → 点【保存】，状态显示【已连接】即成功
TRAE 【设置】→【MCP】→【手动添加】 粘贴 JSON → 点【确认】，然后切到【Builder with MCP】模式
其他客户端 设置里搜关键词 MCP 找「添加服务器 / Add Server / Server 配置」按钮，选 JSON 或手动填写

找不到入口时，直接在客户端设置页的搜索框敲 MCP 三个字母，基本都能定位。 具体菜单位置会随版本变化，以你客户端里的实际显示为准。

2.2 判断你的客户端合不合格

只需要看一点：支不支持 Streamable HTTP 类型的远程 MCP。

三家官方 MCP 都是远程服务（不用在本地装任何软件），配置里会出现 "type": "streamablehttp"，或者直接只给一个 url。

如果你的客户端只支持 command + args 那种本地方式也没关系——高德提供本地版（用 npx 启动）；瑞幸和麦当劳则必须用远程方式。

第 3 章 第二步：领三把钥匙（重点章节）

3.1 瑞幸咖啡 Token

入口：手机浏览器打开 https://open.luckincoffee.com/mcp

页面长什么样：顶部导航有 logo「luckin coffee」，导航项为 MCP / CLI / Skill / 工具文档，右侧有个「登录」按钮。页面上有两个大按钮：「立即接入」和「查看工具文档」。

操作步骤：

  1. 点右上角「登录」按钮，弹出登录框。
  2. 登录框里有两个输入框：一个写着「请输入手机号」，一个写着「请输入6位短信验证码」。
  3. 填手机号，点「获取验证码」，收到短信后填入验证码。
  4. 勾选「我已阅读并同意《瑞幸咖啡用户协议》《瑞幸咖啡隐私权政策》」。 - 不勾选的话，「登录」按钮是灰的，点不动。这一步最多人卡住。
  5. 点「登录」，完成。
  6. 登录后回到 MCP 页面，找到快速接入区块里的配置代码块，右上角有「复制」按钮，把里面的 Token 复制出来。

配置代码块页面原文长这样：

{
  "mcpServers": {
    "my-coffee": {
      "type": "streamablehttp",
      "url": "https://gwmcp.lkcoffee.com/order/user/mcp",
      "headers": {
        "Authorization": "Bearer <登录后复制Token替换>"
      }
    }
  }
}

你要拿走的是：Bearer 后面那一串（不含 Bearer 这个词本身，也不含尖括号）。

关于有效期：页面写的是「持久在线——登录状态保留一个月，免去频繁登录，日常使用更省心」。页面没有单独的"Token 有效期"字段说明。通俗理解：大约一个月要重新登录一次拿新 Token。

接入地址（不用你改）：https://gwmcp.lkcoffee.com/order/user/mcp

瑞幸能干什么：官方「工具文档」页共 8 个工具——

分类 工具名 作用
门店 queryShopList 查门店列表
商品 searchProductForMcp 搜商品
商品 switchProduct 切换规格（官方接口有缺陷，可能报非法参数）
商品 queryProductDetailInfo 查商品详情
订单 previewOrder 订单预览（下单前确认）
订单 createOrder 创建订单
订单 queryOrderDetailInfo 查订单详情
订单 cancelOrder 取消订单

3.2 麦当劳 MCP Token

入口：手机浏览器打开 https://open.mcd.cn/mcp/doc

页面长什么样：标题「麦当劳MCP平台」，右上角导航有「首页 / 接入指南 / 商户平台 / 登录」。左侧文档目录第一项就是「申请 MCP Token」。

操作步骤（页面原文五步）：

  1. 第一步：点击右上角「登录」按钮。 - 注意：点完是跳转到独立登录页，不是弹窗，别以为点错了。
  2. 第二步：在登录页用手机号验证登录。 - 登录页显示「欢迎登录麦当劳」，左侧国家码 +86；两个输入框分别是手机号和「请输入6位短信验证码」；按钮是「获取短信验证码」。 - 下方勾选框：「已阅读并同意《麦当劳会员协议》《麦当劳隐私政策》及《使用条款》」。 - 然后点「登录」。
  3. 第三步：登录成功后返回首页，原来的「登录」按钮会变成「控制台」按钮。点「控制台」，弹出控制台弹窗。
  4. 第四步：弹窗里有「MCP服务状态」「接入指南」「Token」栏，点「激活」按钮申请 MCP Token。
  5. 第五步：弹出服务协议（金拱门（中国）有限公司提供），点「同意」（旁边是「不同意」）。之后 Token 申请成功，点「一键复制」。

弹窗里还有一句提示：「此 MCP Token 代表您的麦当劳会员身份，请严禁分享！」——别发群里。

你要拿走的是：那串 MCP Token。

接入地址：https://mcp.mcd.cn｜认证方式：请求头 Authorization: Bearer YOUR_MCP_TOKEN

限流：每个 Token 每分钟最多 600 次请求，超了返回 429。 错误码：401 = Token 无效/过期/没提供；429 = 触发限流。

麦当劳能干什么：官方工具列表共 32 个工具，分六类——

分类 数量 代表工具
点餐 13 query-nearby-stores 查附近门店、query-meals 查在售餐品、calculate-price 算价、create-order 下单、delivery-query-addresses 查配送地址
互动与内容 4 campaign-calendar 活动日历、draw-lottery 积分抽奖、query-my-prizes 我的奖品
麦麦省领券 3 available-coupons 券列表、auto-bind-coupons 一键领券、query-my-coupons 我的券
麦麦商城/积分 6 query-my-account 查积分、mall-points-products 商城商品、mall-create-order 积分兑换
主题活动 5 query-party-city 活动城市、party-order-create 活动订单创建
通用 1 now-time-info 当前时间

3.3 高德地图 Key

入口：https://lbs.amap.com/api/mcp-server/create-project-and-key

操作步骤（页面原文四步）：

  1. 登录控制台：登录高德开放平台控制台。没有开发者账号就先注册成为开发者。
  2. 创建新应用：进入【应用管理】，点击页面右上角【创建新应用】，填写表单创建应用。
  3. 创建 Key：进入【应用管理】，在"我的应用"里选中刚建的应用，点击【添加 Key】。 - 关键一步：表单里的「服务平台」选择【Web 服务】。选错类型会导致鉴权失败。
  4. 获取 Key：创建成功后拿到 Key 和安全密钥。 - Key 在【应用管理】应用列表里查看，列表列有：Key名称 / Key / 安全密钥 / 绑定服务 / 操作。点 Key 列即可复制。

添加 Key 弹窗的字段：弹窗标题形如「为「你的应用名」添加 Key」，字段有 Key名称、服务平台（选 Web服务）、IP白名单（可不填），底部按钮「取消」「提交」。

配置地址（把 KEY 换成你的）：

https://mcp.amap.com/mcp?key=你的KEY

高德能干什么：地理编码（地名转坐标）、路径规划（驾车/公交/步行/骑行）、POI 搜索、周边搜索、距离测算、IP 定位等约 9 项地图工具。

第 4 章 第三步：填配置

4.1 填空对照表（这就是你要填的全部）

要填的位置 填入什么 从哪来
瑞幸 Authorization Bearer + 瑞幸Token 第 3.1 章
麦当劳 Authorization Bearer + 麦当劳Token 第 3.2 章
高德 URL 里的 key= 你的高德 Key 第 3.3 章

注意：Bearer 和 Token 之间有一个空格，这个空格不能少。

4.2 完整配置模板（直接复制，只改三个地方）

{
  "mcpServers": {
    "luckin-coffee": {
      "type": "streamablehttp",
      "url": "https://gwmcp.lkcoffee.com/order/user/mcp",
      "headers": {
        "Authorization": "Bearer 这里换成你的瑞幸Token"
      }
    },
    "mcd-china": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer 这里换成你的麦当劳Token"
      }
    },
    "amap-maps": {
      "type": "streamablehttp",
      "url": "https://mcp.amap.com/mcp?key=这里换成你的高德Key"
    }
  }
}

4.3 高德本地版（可选，远程版够用就别折腾）

{
  "mcpServers": {
    "amap-maps-local": {
      "command": "npx",
      "args": ["-y", "@amap/amap-maps-mcp-server"],
      "env": {
        "AMAP_MAPS_API_KEY": "这里换成你的高德Key"
      }
    }
  }
}

本地版前提：电脑装了 Node.js，版本 v22.14.0 或以上。

4.4 不想全上？只填你要的那一段就行

三家互不依赖。只想要咖啡，就只保留 luckin-coffee 那一段，其余整段删掉。JSON 的大括号配对别删错就行。

第 5 章 第四步：重启并验证

  1. 保存配置后，完全退出客户端再重新打开（不是关窗口，要真正退出进程）。多数客户端不重启不会加载新 MCP。
  2. 打开后进入 MCP 设置页，看三个服务的状态点： - 绿色/显示「已连接」= 成功 - 红色/显示「失败」= 看第 6 章排查
  3. 看工具数量：瑞幸应显示 8 个左右、麦当劳 30+ 个、高德 9 个左右。数量对得上，说明真连上了。
  4. 用一句话验证（选你能立刻判断对错的）：
服务 对它说 预期反应
瑞幸 「帮我找一下附近的瑞幸门店」 真的返回门店列表，而不是说"我无法查询"
麦当劳 「查一下我麦当劳的积分」 返回真实积分数
高德 「把北京南站转成经纬度」 返回真实坐标

说对了就是配好了。注意：如果 AI 只是"编"了一个店名给你，那是它没真调工具在瞎说——去看客户端里工具调用日志确认。

  1. 下单类操作先别急。第一次测试用"查询"类指令，确认无误后再试下单。

第 6 章 出问题了怎么查（对照表）

现象 原因 怎么修
状态显示 401 Token 错了、过期了、或没带 检查是否写了 Bearer（带空格）；重新登录领新 Token
状态显示 403 凭据无效（麦当劳无凭据时也会返回 403） 确认 Token 完整复制，没多复制空格或换行
状态显示 429 调用太频繁（麦当劳 600 次/分钟上限） 等一分钟再试，降低调用频率
高德提示 INVALID_USER_KEY Key 类型选错或 Key 无效 确认「服务平台」选的是 Web 服务，不是 Web端/Android/iOS
配置保存后没反应 客户端没重启 完全退出进程再打开
JSON 保存报错 括号/逗号/引号出错 把配置粘到 JSON 校验网站检查；注意最后一项后面不能有逗号
找不到 MCP 入口 客户端版本太老或界面差异 设置里搜 MCP；或升级客户端
服务显示已连接但 AI 不调用 客户端没开工具调用/Agent 模式 确认处于 Agent / 工具调用模式（如 TRAE 要切到 Builder with MCP）
瑞幸改杯型/糖度失败 官方 switchProduct 接口缺陷 换不了，只能按默认规格下单，拿到手再说
Token 泄露了怎么办 —— 立刻回对应平台重新申请/重置 Token，旧的作废

第 7 章 安全提醒（别跳这段）

  1. Token 等于你的账号身份。麦当劳官方原话是「此 MCP Token 代表您的麦当劳会员身份，请严禁分享」。不要发到群聊、不要截图发社交平台、不要提交到公开的代码仓库。
  2. 别把带真 Token 的配置文件发给别人。分享配置模板时，先把 Token 换成占位符。
  3. 涉及花钱的操作（下单、兑换）建议先手动确认。AI 会自动匹配优惠券下单，但下单前最好让它先给你确认一遍门店、商品、价格。
  4. Token 有期限。瑞幸约一个月，麦当劳以平台说明为准。用着用着突然报 401，大概率就是过期了，重新领一次即可。

第 8 章 给不同角色分配不同能力（进阶）

如果你使用的客户端支持"角色/Char"配置，可以按下面的思路分配，避免一个角色挂一堆无关工具导致它乱调：

角色定位 建议挂载 理由
咖啡搭子 瑞幸 功能单一，不容易调错
干饭搭子 麦当劳 点餐/领券/积分一类归拢
出行助手 高德（+ 火车票类 MCP） 路线规划为主
全能搭子 三家全挂 方便，但工具多，AI 选错工具概率上升

经验：挂的工具越多，AI 越容易"拿错工具"。宁可分角色，也不要一个角色挂二十个服务。
